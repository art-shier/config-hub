# ConfigHub Web 国际化设计

日期：2026-08-31
状态：设计已确认，待实现计划

## 1. 背景与目标

ConfigHub Web 管理端当前将英文界面文案直接写在 React 组件中，浏览器语言、界面语言、日期格式和无障碍文案之间没有统一的 locale 边界。本次为 Web 管理端建立可维护的国际化基础，并完整提供简体中文与英文界面。

目标：

- 支持 `zh-CN` 和 `en-US`；
- 未手动选择时跟随浏览器语言；
- 记住用户的手动选择，并在刷新和重新登录后保持；
- 语言切换立即作用于可见文案、无障碍文案、错误提示和日期格式；
- 保持 API、CLI、业务数据和现有权限/工作流语义不变；
- 通过类型检查、资源一致性测试、组件测试和端到端测试防止翻译遗漏与回归。

## 2. 范围

### 2.1 包含

- `/login`、鉴权加载状态和未找到页面；
- 应用顶部栏、主导航、语言选择器和退出流程；
- Projects、Project、Configuration、Versions、Project Members、Machine Access、Members、System 页面及其所有状态；
- 按钮、标签、说明、表头、占位内容、空状态、加载状态、错误状态、表单验证、确认弹窗和状态消息；
- `aria-label`、可访问名称、屏幕阅读器状态和其他用户可感知的辅助文案；
- 日期与时间的 locale 格式化；
- 前端根据稳定 API 错误码及字段键生成的本地化提示；
- 语言识别、切换、持久化、回退与资源完整性测试。

### 2.2 不包含

- CLI 输出和命令帮助；
- HTTP API 响应正文及服务端日志的多语言化；
- README、运维文档和产品规格的翻译；
- 用户资料中的服务端语言偏好；
- URL 路径或查询参数中的 locale；
- 项目名、环境名、配置键值、版本说明、用户名等业务数据的翻译；
- 新增其他语言或远程翻译管理平台。

## 3. 语言策略

支持语言固定为：

| Locale | 选择器名称 | HTML `lang` |
|---|---|---|
| `zh-CN` | 简体中文 | `zh-CN` |
| `en-US` | English | `en-US` |

初始化顺序：

1. 读取本地持久化的有效 locale；
2. 若没有有效值，按 `navigator.languages`、`navigator.language` 的顺序匹配；
3. `zh` 或 `zh-*` 匹配 `zh-CN`，`en` 或 `en-*` 匹配 `en-US`；
4. 其他浏览器语言回退到 `en-US`。

用户手动切换后立即更新 React 界面和根元素 `document.documentElement.lang`，并将选择写入一个带 ConfigHub 前缀的 localStorage 键。本地存储读取或写入失败不得阻止应用加载或当前会话内的语言切换。语言偏好不是敏感数据，不与登录 Session 或具体账号绑定。

## 4. 技术方案

采用 `i18next` 与 `react-i18next`：

- `i18next` 负责资源、插值、复数、locale 回退和语言切换；
- `react-i18next` 提供 React Provider 与组件 Hook；
- 初始化在应用入口完成，国际化 Provider 位于路由和认证 Provider 外层，从而覆盖登录前、鉴权中和登录后的全部界面；
- 两种语言资源随 Web 首屏静态打包，不使用运行时网络加载，避免文案闪烁、加载失败和额外缓存状态；
- 启用安全插值默认行为，不将翻译资源或服务端文案作为 HTML 注入。

不采用自研 Context 字典，原因是它会重复实现复数、缺失键、插值和测试适配；不采用 FormatJS，原因是本项目当前没有复杂 ICU 消息或货币规则，其引入成本高于收益。

## 5. 资源组织与边界

翻译资源按业务域拆分为以下命名空间：

- `common`：共享动作、状态、角色、导航和通用错误；
- `auth`：登录、Session 检查和退出；
- `projects`：项目列表、创建和项目详情；
- `config`：配置查看、搜索、编辑、验证和冲突比较；
- `versions`：版本列表、差异和回滚；
- `members`：全局成员及项目成员；
- `machineAccess`：机器身份、授权、Token 和一次性密钥显示；
- `system`：运行状态和安全字段说明。

资源键使用稳定的语义名称，不使用英文原句作为键。带变量的文案通过插值生成；数量相关文案使用 i18next 复数规则。`en-US` 是最终回退资源，但正常发布必须保证两种语言的命名空间和键集合完全一致，不能依靠回退掩盖缺失翻译。

系统枚举保持 API 原值不变，只在展示层映射：

- `admin`、`member`；
- `viewer`、`editor`；
- 启用、禁用、撤销、过期等状态；
- added、changed、deleted 等差异类型。

项目 slug、环境 slug、配置 Key/Value/Service、用户名、显示名、版本说明、Token 前缀和构建版本等用户或系统数据原样显示。

## 6. 组件与交互

新增共享语言选择器，在两个位置复用：

- 登录页：不依赖 Session，用户可在登录前选择；
- 应用顶部栏：登录后可随时切换。

选择器使用带可见标签的原生 `<select>`。操作系统原生弹出层在本场景可接受，并可复用成熟的键盘、触摸和屏幕阅读器行为。选项名称使用对应语言自己的写法“简体中文”和“English”，避免切换后无法识别另一语言。

选择器沿用现有颜色、字体、边框、焦点和响应式体系，不重新设计应用视觉风格。宽度为稳定的内容宽度，切换语言不应移动主要导航或会话操作；窄屏下必须与现有导航按钮、用户信息和退出按钮共存。

所有界面文案都从资源读取，包括隐藏或条件状态。原有按钮语义、确认强度、焦点管理、加载/禁用状态和导航结果保持不变。语言切换不重置表单、搜索、当前路由、选中环境、编辑草稿或弹窗状态。

## 7. 日期、文本处理与文档语言

建立共享日期格式化接口，显式接收当前 locale，并替换页面内重复的 `Intl.DateTimeFormat(undefined, ...)`：

- 日期使用现有 `dateStyle: "medium"` 语义；
- 日期时间使用现有 `dateStyle: "medium"`、`timeStyle: "short"` 语义；
- 继续使用浏览器本地时区，不在本次引入新的业务时区；
- 无效日期返回当前语言的“不可用”提示；
- 格式化失败时采用稳定且不泄露数据的回退显示。

搜索仍对配置 Key 与 Service 做不区分大小写的本地过滤；业务标识不按界面语言翻译。根元素 `lang` 随 locale 同步，使浏览器、辅助技术和字体回退使用正确的语言信息。页面标题 `ConfigHub` 是产品名，不翻译。

## 8. 错误处理

服务端继续返回统一错误 envelope，`code` 和字段键是前端本地化的稳定输入。前端不得直接把服务端 `message` 或字段中的英文说明作为最终界面文案。

处理顺序：

1. 组件根据业务上下文和稳定 `code` 选择精确提示；
2. 表单错误根据稳定字段键映射到本地字段提示；
3. 未知错误使用当前页面的本地化安全通用提示；
4. request ID 仅在现有产品流程明确需要时展示，不把响应正文、配置值、密码或 Token 写入提示。

`401` 仍触发现有 Session 清理，`409 revision_conflict` 仍进入刷新比较流程，`422` 仍保留字段定位，`429` 和 `503` 仍保留现有恢复建议。国际化不得改变认证、权限、冲突和副作用行为。

## 9. 可访问性与布局稳定性

- 目标保持 WCAG 2.2 AA；
- 语言选择器有真实 `<label>`、键盘焦点、明确名称和当前值；
- 所有图标按钮、导航开关、弹窗和状态消息的可访问文案随 locale 更新；
- 切换语言后不主动移动焦点；屏幕阅读器通过控件当前值与后续界面内容感知变化；
- 两种语言下按钮和加载态保持相同容器尺寸，避免异步或切换引发布局跳动；
- 验证桌面、窄屏、200% 缩放、键盘操作和减少动态效果设置；
- 中文采用现有系统字体栈中的合适 CJK 回退，不为本次改动增加外部字体下载。

## 10. 测试与验收

### 10.1 单元测试

- locale 规范化及浏览器语言匹配；
- 持久化值优先级、无效值回退和 localStorage 异常；
- 切换语言后 Provider 状态及 `<html lang>` 同步；
- `zh-CN` 与 `en-US` 的命名空间和资源键完全一致；
- 日期与日期时间按显式 locale 格式化；
- 未知/已知 API 错误不会泄露服务端原始英文或敏感正文。

### 10.2 组件测试

- 现有英文测试在明确的 `en-US` 测试 Provider 下继续通过；
- 登录页和应用壳层验证中文切换及共享选择器；
- 至少覆盖项目、配置、版本、机器访问和系统页面的中文关键状态；
- 验证 ARIA 文案、弹窗、验证错误、加载、空状态和失败恢复文案；
- 验证语言切换不会丢失当前组件状态。

### 10.3 端到端测试

- 浏览器语言为中文且没有持久化偏好时显示简体中文；
- 登录前切到英文，登录后保持英文；
- 登录后切到中文，导航并刷新后仍保持中文；
- 中文下完成现有核心流程的代表性读写操作；
- 在桌面和窄屏验证选择器、导航及主要动作不重叠；
- 验证日期格式、错误恢复、键盘操作和可访问名称。

### 10.4 完成门槛

- 前端类型检查、单元测试、构建和 Playwright E2E 全部通过；若实现时新增或发现项目维护的格式化命令，也必须通过；
- 仓库完整检查脚本通过；
- 国际化静态审计没有缺失键、直接泄漏的服务端消息或新增硬编码用户界面文案；
- `zh-CN` 与 `en-US` 下人工或浏览器验收核心页面；
- 不改变 API、CLI、数据库或权限行为。

## 11. 预期文件边界

实现预计涉及：

- `web/package.json` 与锁文件：新增国际化依赖；
- `web/src/i18n/`：初始化、locale 解析、格式化、类型和分域资源；
- `web/src/components/LanguageSwitcher.tsx`：共享语言选择器；
- `web/src/main.tsx` 或应用根组件：挂载国际化 Provider；
- 现有页面和功能组件：将用户界面文案替换为翻译键；
- 测试基础设施、组件测试和 E2E：显式 locale 与新增覆盖；
- `web/src/styles.css`：语言选择器及两种语言下的稳定布局；
- 项目根 `DESIGN.md`：从现有样式建立轻量、耐久的视觉上下文，并记录语言选择器沿用现有控制样式，不改变视觉身份。

服务端 Go、数据库迁移、CLI 和 HTTP 合同不需要实现改动。

## 12. 风险与控制

- **遗漏硬编码文案**：资源一致性测试、静态搜索和逐页中英文验收共同控制；
- **测试受机器浏览器语言影响**：测试 Provider 明确指定 `en-US`，只在专用用例模拟语言检测；
- **服务端英文泄漏**：按错误码/字段键映射并测试敏感原文不出现在 DOM；
- **切换语言丢失编辑状态**：Provider 只改变 locale，不重建路由、认证或页面状态树；
- **窄屏顶部栏拥挤**：使用共享紧凑控件并进行窄屏和 200% 缩放验证；
- **翻译键长期漂移**：按业务域拆分、类型约束并强制两种资源键集合一致。
